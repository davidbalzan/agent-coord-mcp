## Queue

- [ ] (P1) **Recurring `agent-coord-mcp` self-dependency in `package.json` + `package-lock.json`** — a self-dep (`"agent-coord-mcp": "^0.x"`, now `^0.8.0`) keeps reappearing in `dependencies`, making the package depend on an old published copy of itself and breaking `npm install`; removed once during v0.8.0 work. **Needs David ruling** — flagged "intentional" in this environment but reads as a defect; confirm before fixing · acceptance: line gone from both files, the re-add source (linter/hook/`npm i <self>` misfire) identified and stopped, `npm install` clean from a fresh clone.
- [ ] (P2) **Guard first-use identity binding against claiming a live agent id** — a fresh MCP session binds to the first agentId it sees (when `AGENT_COORD_BOUND_AGENT` is unset); even a diagnostic `status {agentId}` claims it, silently creating a second session acting as an already-registered, heartbeating agent (hit live 2026-07-06: a dev session bound itself to `disavow-liaison`) · acceptance: (1) binding to an id with a fresh heartbeat or live transport marker requires that agent's token (`coord-token`) or an explicit `force`; (2) read-only tools (`status`, `ping`) never establish a binding; (3) `doctor` warns when two live sessions bound the same id.
- [ ] (P3) **`doctor` reaper for wedged pushers (pid-alive, pane-dead)** — v0.8.0 made pushers self-exit on a dead pane, but a pusher that's alive yet whose pane is gone is still reported "live" by `list_agents` and missed by `doctor` (distinct from the v0.8.2 stale-pusher-script check) · acceptance: probe each local `tmux-push` marker's `tmuxTarget`; under `fix:true`, SIGTERM the pusher + clear the marker; host-local only.
- [ ] (P3) **Pusher safety: pane outlived the agent as a bare shell** — if a pane survives after the agent CLI exits, peer messages paste into the shell (self-exit misses it, the pane is alive); RISK — typing into a live shell is the worst failure mode of the transport · acceptance: detect via `pane_current_command` and refuse to inject / self-exit.
- [ ] (P3) **Encrypted DMs (ROADMAP Phase 7)** — per-agent keypairs; encrypt `inbox/*.jsonl` payloads so the local-storage-readable threat model goes away; core bus feature, large · acceptance: DM payloads encrypted at rest, decryptable only by the recipient agent.
- [ ] (P3) **Lightweight message reactions/acks in the JSONL model** — let an agent ack a peer ping without a full message (a `react`-flagged entry) to reduce room noise; low urgency (coordinator protocol uses `post_status` today) · acceptance: a `react`-flagged entry type peers/`list` can surface without a full message.
- [ ] (P2) **`doctor` treats a MISSING `scriptMtime` as a skip, not a warn** — the stale-pusher-script check silently exempts any marker lacking the field, and the pusher's own marker write was what dropped it, so the check that would have caught a stale pusher was disabled by the very thing it monitors; a health check whose precondition is written by its subject cannot fail loudly (found live 2026-07-28, credit `agent-coordination-david-dev`) · acceptance: a live local `tmux-push` marker with no `scriptMtime` reports `warn` ("cannot verify — re-attach"), never `ok`; test pins that a missing field is not silently exempt.
- [ ] (P2) **The live bus executes from a mutable dev checkout** — every agent's MCP server and every `tmux-push` pusher resolves to the primary checkout (`resolvePusherPath`, and the user-scope MCP config's absolute `dist/server.js` path), regardless of which git worktree that agent works in; worktrees isolate editing, not execution. A `git checkout` in the primary tree silently changes behaviour for every agent on the bus at their next restart/spawn, and `stale-pusher-script` cannot detect it because scriptMtime moves too, so markers look fresh while behaviour reverts. Surfaced during the Phase 8 rollout · acceptance: execution resolves from an installed/pinned artifact rather than a live working tree, or `doctor` reports the resolved checkout's branch+SHA so drift is at least visible.
- [ ] (P2) **Gate authority is delegated per-task, but record authority is bound to a role** — Task 4 restricts the `verdict` record type to gate-runner roles, while gating is assigned per task by the coordinator; a worker asked to gate someone else's commit can therefore only issue its verdict as plain text (losing typed routing) or re-register into a gate role, which is the self-declared authority the check exists to prevent. Hit live 2026-07-28 when `ai-workflow-worker-1` gated claude-code's Tasks 1–2 · acceptance: a coordinator can grant per-task gate authority without permanently re-roling the worker, or record authority understands "gate for THIS task"; self-declaration remains impossible either way.
- [ ] (P2) **Gate independence is weaker than the worktree boundary suggests** — `git worktree` shares one object database, so a worker gating the coordinator's code can resolve commits the coordinator made LOCALLY and never pushed, including ones rewritten by an amend/force-push; a gate that assumes it only sees published history is unsound here. Found 2026-07-28 by `ai-workflow-worker-1` re-gating fd8674b, after claude-code wrongly asserted a force-pushed commit "no longer exists" (it still resolved in the worker's worktree). Same root as the mutable-checkout item above, surfacing in the gate path; blast radius grows with each worktree (4 today) · acceptance: gating verifies against a fetched remote ref, not a shared object store — or the gate runs from a genuinely separate clone.
- [ ] (P1) **Phase 8: Typed protocol** — promote the workflow protocol (escalation tiers, decision packets, citations, write scopes, role identity, work state) from case-sensitive string parsing to typed records the server understands; strictly additive so v1 and v2 agents share a bus.
