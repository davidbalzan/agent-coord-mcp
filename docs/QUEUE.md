recorded in `docs/DONE.md`. Priority via the `(P1)`/`(P2)`/`(P3)` tag; top-to-bottom breaks ties.

this file; it reads the top unblocked item fresh and appends its completion to `docs/DONE.md`.

Two uncovered steps: `dist/` was not rebuilt, and every running MCP server holds pre-merge code in memory (node loads once at startup). So `attach_agent` stamped using OLD single-file logic while `doctor` compared against NEW on-disk state. - [ ] (P1) **A `coord-worker` parks a draft in its input, so `/clear` and `/compact` can never reach it** — control commands correctly refuse to paste into a pane with unsent text (#21), but a coord-worker types self-continue text into its input every time it idles (`wait for the coordinator's reply`, `wait for the gate verdict`). Its two states are BUSY or DRAFTED — never idle-and-empty — so the refusal fires every time. Three separate live attempts against `ai-workflow-worker-1` on 2026-07-29 were all refused, and test 1 had to be run against a purpose-spawned probe agent instead. Net effect: context management, the feature `send_command` exists to provide, is unusable against the fleet it was built for. The refusals are CORRECT — the defect is the interaction, not the guard · acceptance: either the worker protocol stops parking text in the input when idle, or the control path can safely stash-and-restore a draft (clear the input, run the command, retype the draft) with the draft provably intact on failure; decided deliberately, because silently typing over a human's or an agent's unsent text is the worse failure.

- [ ] (P2) **The live bus executes from a mutable dev checkout** — every agent's MCP server and every `tmux-push` pusher resolves to the primary checkout (`resolvePusherPath`, and the user-scope MCP config's absolute `dist/server.js` path), regardless of which git worktree that agent works in; worktrees isolate editing, not execution.
