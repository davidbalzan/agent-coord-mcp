# QUEUE — agent-coord-mcp

The inbound task queue. Ad-hoc tasks and phase items are added here by the human (or their planning
proxy, the liaison). Intake only: live in-flight state lives in [[WORKSTREAMS]], completions are
recorded in `docs/DONE.md`. Priority via the `(P1)`/`(P2)`/`(P3)` tag; top-to-bottom breaks ties.

**Write rule (single writer per file):** the human / liaison writes here — add / reorder / remove /
edit items, set priority, add acceptance criteria or refs inline. Whoever executes work never edits
this file; it reads the top unblocked item fresh and appends its completion to `docs/DONE.md`.

Every gate verdict issued while this stands is suspect in one direction — a FAIL may be noise. **RESOLVED 2026-07-29 — davidbalzan/agent-coord-mcp#31, and the cause is NOT what this entry spent three sightings assuming.** `david-worker-2` instrumented every process in the test tree (preload tracer, once+re-raise so `signalCode` semantics survive): the dummy child takes doctor's SIGTERM correctly, and the TEST PROCESS TAKES NO SIGNAL AT ALL — just `beforeExit` 6ms later. Nothing kills the runner; its event loop DRAINS. Root cause is a missed-event race at `doctor.test.mjs:268`: `doctor({fix:true})` SIGTERMs the dummy mid-call, the child's `'exit'` fires during doctor's remaining awaits, and a `once("exit")` attached AFTERWARDS waits forever on an event that already happened — child dead, no live handles, loop drains, every remaining subtest in the file reports `cancelledByParent`. The one that resolved it went and MEASURED which processes received signals.**
